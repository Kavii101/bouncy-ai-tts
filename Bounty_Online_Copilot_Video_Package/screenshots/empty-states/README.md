# Empty states — rebuildable product shells

Standalone HTML for every Bounty Online co-pilot module **before anything
happens**. They exist so a producer or animation AI can rebuild the real
product, animate transitions into populated states, make editorial
decisions, and apply any house style — without running the app.

Open `index.html` for the gallery, or any file directly:

| File | Module | State |
|---|---|---|
| `01-listen.html` | Listen | Empty composer, natural-voice selector |
| `02-setup-empty.html` | Setup | No materials, demo restore, PDF coming-soon |
| `03-brief-empty.html` | Brief | No brief yet |
| `04-practice-locked.html` | Practice | Locked until brief approval |
| `05-sql-empty.html` | SQL Lab | No solution yet |
| `06-present-empty.html` | Present | No cue cards yet |
| `07-live-consent-idle.html` | Live | Consent gate + idle stage description |
| `08-answers-waiting.html` | Answers | Waiting for the control window |
| `09-prompter-no-talk.html` | Prompter | No talk loaded, welcome pose |
| `10-subtitles-idle.html` | Subtitles | Idle before Start |

Rules: copy and layout mirror the real product (see `../shell-data.json`
for verbatim text); restyle freely for film, but never present an empty
state as a completed result, and never alter the mascot images (referenced
from `../../assets/mascot/web/`).
